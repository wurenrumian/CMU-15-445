# Row Store vs Column Store

行存储把一条记录连续放在一起，适合点查和事务更新；列存储把同一列的数据聚拢，适合扫描少数列的大型分析查询。

```text
Row:    Alice | 20 | CS     Bob | 21 | Math
Column: Alice | Bob          20 | 21          CS | Math
```

列式布局让压缩和 SIMD 批处理更有效。BusTub 的向量化执行（P3）已经把“批量处理”带入执行器；DuckDB、ClickHouse 则进一步把它和列式存储结合起来。

| 工作负载 | 更合适的布局 | 原因 |
|---|---|---|
| OLTP：单行读写、短事务 | 行存储 | 一次 I/O 获得整条记录 |
| OLAP：聚合、扫描少数列 | 列存储 | 少读数据，压缩率高 |
| 混合负载 | 分层或混合方案 | 热数据与历史数据采用不同布局 |
