# 磁盘、SSD 与 I/O

数据库的许多设计，都是在回答同一个问题：一次 I/O 到底有多贵？

- **延迟**：一次请求要等多久。随机读通常比顺序读更昂贵。
- **吞吐**：单位时间能搬运多少数据。批量、顺序请求更容易跑满设备。
- **放大**：用户写入 1MB，底层可能实际读写更多数据。LSM 的 Compaction 会产生写放大。

HDD 受寻道和旋转延迟影响，顺序访问优势明显；SSD 没有机械寻道，但随机访问仍有队列、擦除、映射和持久化开销。因此 Buffer Pool、预取、批量 I/O 和 WAL 仍然重要。

`write()` 返回不等于数据已经安全保存。真正的 durable commit 通常需要日志或数据经过 flush / fsync。WAL 把这个昂贵动作集中到顺序日志上，再把脏页延迟写回。
