# 工程实践

完成数据库 Lab 不只是补齐函数，还要验证不变量、定位并发竞态并测量性能。

## 推荐的工程习惯

- 先写出页、索引和事务的不变量，再实现状态变化。
- 用单元测试覆盖边界：空表、重复键、页满、分裂、合并、事务中止。
- 用 ASAN / TSAN 捕获越界、Use-after-free 和数据竞争。
- 区分正确性测试与吞吐测试，避免只追求“测试变绿”。
- 记录一次 SQL 穿过的执行器、索引和页访问路径。

本仓库的 F2025 评分范围共 86 个测试，P0–P4 全部通过，并额外完成可扩展哈希与窗口函数。它们构成了阅读真实数据库源码前的一份可验证样本。

## 从测试反推设计

看到失败测试时，可以按“输入 → 不变量 → 可观察结果”拆开：页满时插入不仅要成功，还要保证所有 Tuple 仍可通过 RID 找到、父节点和叶链正确。并发测试应重复运行，因为一次通过并不能排除竞态。

| 模块 | 核心状态 | 失效时最先检查 |
|---|---|---|
| Buffer Pool | page table、pin、dirty | Guard 生命周期与淘汰顺序 |
| B+Tree | 节点大小、父子指针、叶链 | 分裂/合并后的边界键 |
| MVCC | 时间戳、Undo 链、事务状态 | 可见性判断与中止路径 |
