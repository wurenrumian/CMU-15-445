# 事务与并发

事务把多次读写组织成一个逻辑单元。数据库需要同时提供原子性、一致性、隔离性和持久性（ACID）。

## 2PL 与 MVCC

两阶段锁通过共享锁和排他锁阻止冲突，但长读会阻塞写。MVCC 保留多个版本，让读事务读取自己的时间戳快照；通常只有写写冲突需要协调。

BusTub 使用 `read_ts`、临时时间戳、`commit_ts` 和 Undo Log。Watermark 是活跃事务中最小的 `read_ts`，它决定哪些旧版本已经不可能再被读到。

## 隔离级别

```text
Read Uncommitted → Read Committed → Repeatable Read → Serializable
       弱隔离                                      强隔离
```

隔离越强，异常越少，但冲突检测、锁管理或版本维护的成本越高。P4 的可串行化测试展示了快照读取之外还需要写写冲突检测。

## 一次更新如何变成可见版本

事务更新一行时，系统通常记录带临时时间戳的新版本，而不是立刻覆盖旧值；提交时再写入 `commit_ts`。其他事务根据自己的 `read_ts` 判断版本可见性，必要时沿 Undo 链回溯。中止则按 Undo 信息撤销本事务的修改。

提交和中止都是全局动作：表、索引、版本链和事务状态不能只更新一部分。测试并发事务时，除了最终值，也要检查读到的版本、冲突事务状态以及索引是否仍能定位到正确 RID。
